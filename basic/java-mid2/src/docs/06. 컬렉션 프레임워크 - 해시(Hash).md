# 06. 컬렉션 프레임워크 - 해시(Hash) — 검색을 O(n)에서 O(1)로

## 1. 리스트(List) vs 세트(Set)

| | List | Set |
|---|---|---|
| 순서 | 유지 (인덱스) | 보장 안 함 |
| 중복 | 허용 | **불허** |
| 쓰임 | 장바구니, 순서 있는 목록 | 회원 ID 집합, 중복 제거 |

## 2. 직접 구현하는 Set0 - 시작

[`MyHashSetV0`](../collection/set/MyHashSetV0.java) — 배열에 넣되 넣기 전에 중복 검사.

```java
// 데이터를 추가할 때마다 값이 있는지 중복 검사를 하느라 항상 O(n) 만큼의 연산으로 인해 입력 성능이 나쁘다.
public boolean add(int value) {
    if (contains(value)) {   // 값이 있는지 중복검사 O(n)
        return false;
    }
    elementData[size] = value; // O(1)
    size++;
    return true;
}
```

**Set은 추가할 때마다 검색이 따라붙는다.** 검색이 O(n)이면 추가도 O(n). → 검색을 빠르게 만들어야 한다.

## 3. 해시 알고리즘 — index 사용 → 메모리 낭비 → 나머지 연산

| 단계 | 아이디어 | 결과 |
|------|---------|------|
| [`HashStart2`](../collection/set/HashStart2.java) | **값 = 인덱스**로 저장 (`inputArray[8] = 8`) | 검색 O(1) ✅ |
| [`HashStart3`](../collection/set/HashStart3.java) | 값 99를 넣으려면 배열이 100칸 | 메모리 낭비 ❌ |
| [`HashStart4`](../collection/set/HashStart4.java) | **나머지 연산** `value % CAPACITY` | 작은 배열로 O(1) ✅ |

```java
static final int CAPACITY = 10;
static int hashIndex(int value) {
    return value % CAPACITY;   // 14 → 4, 99 → 9
}
Integer result = inputArray[hashIndex(searchValue)]; // O(1)
```

- **해시 인덱스(hash index)**: 값을 배열 크기로 나눈 나머지 — 저장할 배열 칸 번호.

## 4. 해시 충돌 — 설명과 구현

`99 % 10 = 9`, `9 % 10 = 9` — 다른 값이 같은 칸을 원한다. 이게 **해시 충돌**.

해결: 배열의 각 칸을 값 하나가 아니라 **리스트(버킷, bucket)** 로 만든다 ([`HashStart5`](../collection/set/HashStart5.java)).

```java
LinkedList<Integer>[] buckets = new LinkedList[CAPACITY];
// add(buckets, 99); // 9: [99]
// add(buckets, 9);  // 중복 9: [99, 9] 저장

private static void add(LinkedList<Integer>[] buckets, int value) {
    LinkedList<Integer> bucket = buckets[hashIndex(value)]; // O(1)
    if (!bucket.contains(value)) {                          // 버킷 안에서만 검사
        bucket.add(value);
    }
}
```

```
buckets[0] []
buckets[1] [1]
...
buckets[4] [14]
buckets[9] [99, 9]   ← 충돌: 같은 버킷에 함께 저장
```

- 평균 **O(1)**: 버킷을 한 번에 찾고, 버킷 안은 보통 한두 개.
- 최악 **O(n)**: 모두 한 버킷에 몰릴 때. 그래서 배열 크기에 여유를 둔다 (자바는 **75%** 차면 2배로 늘린다).

⚠️ 내 `HashStart5.contains`는 `bucket.contains(hashIndex)`로 **해시 인덱스를 찾고 있다** — `bucket.contains(searchValue)`여야 한다. 예제에서 `9`의 해시 인덱스도 9라 우연히 `true`가 나왔을 뿐이다.

## ✅ 핵심 요약

- Set은 추가 때마다 중복 검사 → **검색 성능이 곧 추가 성능**.
- 해시 인덱스 = `값 % 배열크기` → 배열 인덱스 접근으로 O(1).
- 충돌은 **버킷(리스트)** 에 함께 저장해 해결. 평균 O(1), 최악 O(n).
