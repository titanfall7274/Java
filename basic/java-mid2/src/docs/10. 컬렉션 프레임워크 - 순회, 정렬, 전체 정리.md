## 1. 순회1 - 직접 구현하는 Iterable, Iterator

자료 구조마다 순회 방법이 다르다(배열은 인덱스, 연결 리스트는 `next`, 해시는 버킷). **순회 방법을 인터페이스로 통일**한 것이 `Iterable` / `Iterator`.

| 인터페이스 | 메서드 | 역할 |
|-----------|--------|------|
| `Iterable<T>` | `iterator()` | "나는 순회할 수 있다" — 반복자를 만들어 준다 |
| `Iterator<T>` | `hasNext()`, `next()` | 실제로 하나씩 꺼내는 반복자 |

```java
public class MyArray implements Iterable<Integer> {
    public Iterator<Integer> iterator() {
        return new MyArrayIterator(numbers);
    }
}
public class MyArrayIterator implements Iterator<Integer> {
    private int currentIndex = -1;
    public boolean hasNext() { return currentIndex < targetArr.length - 1; }
    public Integer next()    { return targetArr[++currentIndex]; }
}
```

## 2. 순회2 - 향상된 for문

**`Iterable`을 구현하면 for-each를 쓸 수 있다.** 컴파일러가 반복자 코드로 바꿔 준다.

```java
for (int value : myArray) { ... }
// 컴파일 시점에 ↓ 로 변경
Iterator<Integer> iterator = myArray.iterator();
while (iterator.hasNext()) {
    Integer value = iterator.next();
}
```

## 3. 순회3 - 자바가 제공하는 Iterable, Iterator

`Collection`이 `Iterable`을 상속하므로 **모든 List·Set·Queue는 for-each가 된다.** (`Map`은 `Collection`이 아니라 `keySet()`/`entrySet()`으로 순회.)

```java
// JavIterableMain — List든 Set이든 같은 메서드로 순회
private static void foreach(Iterable<Integer> iterable) {
    for (Integer i : iterable) { ... }
}
// iterator.getClass() → class java.util.ArrayList$Itr (중첩 클래스)
```

💡 이것이 **이터레이터 패턴** — 내부 구조를 몰라도 같은 방식으로 순회한다.

## 4. 정렬 - Comparable, Comparator

| | `Comparable<T>` | `Comparator<T>` |
|---|---|---|
| 메서드 | `compareTo(T o)` | `compare(T o1, T o2)` |
| 위치 | 정렬 대상 클래스 **안** | 클래스 **밖** 별도 객체 |
| 의미 | 기본(자연) 정렬 기준 — 하나 | 그때그때 다른 기준 — 여러 개 |

반환값: **음수**(앞이 작다) / **0**(같다) / **양수**(앞이 크다) → 오름차순이면 작은 게 앞.

```java
// MyUser — 기본 정렬: 나이 오름차순
public int compareTo(MyUser o) {
    return this.age < o.age ? -1 : ((this.age == o.age) ? 0 : 1);
}
// IdComparator — 다른 기준: 아이디
public int compare(MyUser o1, MyUser o2) {
    return o1.getId().compareTo(o2.getId());
}
```

| 대상 | 기본 정렬 (`Comparable`) | 기준 지정 (`Comparator`) |
|------|-------------------------|-------------------------|
| 배열 | `Arrays.sort(array)` | `Arrays.sort(array, new IdComparator())` |
| List | `list.sort(null)` / `Collections.sort(list)` | `list.sort(new IdComparator())` |
| TreeSet/TreeMap | `new TreeSet<>()` | `new TreeSet<>(new IdComparator().reversed())` |

- 역순: `comparator.reversed()`.
- ⚠️ `Comparable`도 없고 `Comparator`도 안 주면 정렬 시 `ClassCastException`.
- 💡 `TreeSet`은 **넣을 때 정렬**되므로 출력만 하면 된다 ([`SortMain5`](../collection/compare/SortMain5.java)).

⚠️ 내 [`SortMain2.DescComparator`](../collection/compare/SortMain2.java)는 식이 틀렸다.

```java
return (o1 < o2) ? -1 : ((o1 == o2) ? 0 : 1) * -1;
```

`* -1`이 뒤쪽 괄호에만 붙어서, `o1 < o2`여도 `-1`, `o1 > o2`여도 `-1`이 된다 — 비교 규칙이 깨진 비교자다. 예제 입력에선 결과가 우연히 `[3, 2, 1]`로 나왔을 뿐이다. `((o1 < o2) ? -1 : ((o1 == o2) ? 0 : 1)) * -1` 또는 `o2.compareTo(o1)`로 써야 한다. 또 `Integer`끼리 `==`는 참조 비교라 -128~127 밖에서는 틀린다 → `Integer.compare(o1, o2)`가 안전하다.

## 5. 컬렉션 유틸

| 기능 | 코드 | 비고 |
|------|------|------|
| 최대·최소·섞기·정렬·뒤집기 | `Collections.max/min/shuffle/sort/reverse` | [`CollectionsSortMain`](../collection/utils/CollectionsSortMain.java) |
| 불변 컬렉션 | `List.of(1,2,3)`, `Set.of(...)`, `Map.of(k,v,...)` | 수정하면 `UnsupportedOperationException` ([`OfMain`](../collection/utils/OfMain.java)) |
| 불변 → 가변 | `new ArrayList<>(list)` | [`ImmutableMain`](../collection/utils/ImmutableMain.java) |
| 가변 → 불변 | `Collections.unmodifiableList(...)` 등 | |
| 빈 리스트 | 가변 `new ArrayList<>()` / 불변 `List.of()` | [`EmptyListMain`](../collection/utils/EmptyListMain.java) |
| 멀티스레드 동기화 | `Collections.synchronizedList(list)` | [`SyncMain`](../collection/utils/SyncMain.java) |

`Arrays.asList` vs `List.of`:

| | `Arrays.asList(arr)` | `List.of(arr)` |
|---|---|---|
| 원소 변경(`set`) | 가능 | 불가 |
| 크기 변경(`add`/`remove`) | 불가 | 불가 |
| 원본 배열과 관계 | **공유** — 배열을 바꾸면 리스트도 바뀜 | **복사** — 영향 없음 |

```java
// EmptyListMain
List<Integer> arrList = Arrays.asList(arr); // 원본 배열 사이드 이펙트
List<Integer> arrOf = List.of(arr);         // 원본 배열 복사
arr[0] = 2;                                 // arrList는 [2, ...], arrOf는 [1, ...]
```

💡 특별한 이유가 없으면 `List.of`를 쓴다.

## 6. 컬렉션 프레임워크 전체 정리

```
Iterable
 └ Collection
    ├ List  ── ArrayList, LinkedList
    ├ Set   ── HashSet ─ LinkedHashSet,  TreeSet
    └ Queue ── Deque ─ ArrayDeque, LinkedList
Map ── HashMap ─ LinkedHashMap,  TreeMap      (Collection 아님)
```

실무 선택 가이드:

| 상황 | 선택 |
|------|------|
| 순서 있는 목록 | `ArrayList` |
| 앞쪽 삽입·삭제가 아주 많음 | `LinkedList` |
| 중복 없는 집합 | `HashSet` (입력 순 `LinkedHashSet`, 정렬 `TreeSet`) |
| 키로 찾기 | `HashMap` (입력 순 `LinkedHashMap`, 정렬 `TreeMap`) |
| 스택 / 큐 | `ArrayDeque` |

## ✅ 핵심 요약

- `Iterable` 구현 → for-each 가능. 모든 `Collection`은 `Iterable`.
- 기본 정렬은 `Comparable.compareTo`, 다른 기준은 `Comparator` 객체. 역순은 `reversed()`.
- 불변은 `List.of`, 수정하려면 `new ArrayList<>(...)`로 복사. `Arrays.asList`는 원본 배열과 공유.
- 기본 선택: `ArrayList` / `HashSet` / `HashMap` / `ArrayDeque`.
