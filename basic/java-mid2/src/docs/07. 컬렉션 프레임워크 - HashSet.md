## 2. 문자열 해시 코드

`int`가 아닌 값(문자열 등)은 **먼저 숫자로 바꿔야** 해시 인덱스를 구할 수 있다 ([`StringHashMain`](../collection/set/StringHashMain.java)).

```java
private static int hashCode(String str) {
    int sum = 0;
    for (char c : str.toCharArray()) {
        sum += (int) c;          // 'A' = 65, 'B' = 66
    }
    return sum;
}
// hashIndex('AB') = 131 % 10 = 1
```

| 용어 | 뜻 |
|------|----|
| 해시 함수 | 임의 데이터 → 고정 크기 정수로 바꾸는 함수 |
| 해시 코드 | 해시 함수의 결과 정수 |
| 해시 인덱스 | 해시 코드를 배열 크기로 나눈 나머지 |

## 3. 자바의 hashCode()

모든 객체는 `Object.hashCode()`를 갖는다 ([`JavaHashCodeMain`](../collection/set/JavaHashCodeMain.java)).

- `Object` 기본 구현: **참조값 기반** → 내용이 같아도 인스턴스가 다르면 다른 값.
- `String`, `Integer` 등은 **내용 기반으로 이미 오버라이딩**되어 있다 (`"A".hashCode()` = 65).
- 해시 코드는 **음수일 수 있다** → 인덱스 계산 시 `Math.abs()`.

## 4. 직접 구현하는 Set2 - MyHashSetV2

[`MyHashSetV2`](../collection/set/MyHashSetV2.java) — `Object`를 받아 어떤 타입이든 저장.

```java
private int hashIndex(Object value) {
    // hashCode의 결과로 !음수!가 나올 수 있다.
    // 때문에 abs()를 사용해서 마이너스를 제거한다.
    return Math.abs(value.hashCode()) % capacity;
}
```

## 5. 직접 구현하는 Set3 - 직접 만든 객체 보관

직접 만든 `Member`를 넣으려면 `hashCode()`와 `equals()`를 **둘 다** 오버라이딩해야 한다.

```java
// collection.set.member.Member
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Member member = (Member) o;
    return Objects.equals(id, member.id);
}
@Override
public int hashCode() {
    return Objects.hashCode(id);   // 필드가 여러 개면 Objects.hash(a, b)
}
```

## 6. equals, hashCode의 중요성

해시 자료 구조는 **`hashCode()`로 버킷을 찾고, `equals()`로 버킷 안에서 같은 값을 찾는다.** 하나라도 빠지면 깨진다.

| 예제 | hashCode | equals | 결과 |
|------|:---:|:---:|------|
| [`HashAndEqualsMain1`](../collection/set/member/HashAndEqualsMain1.java) `MemberNoHashEq` | ❌ 참조 기반 | ❌ 참조 비교 | 같은 id가 **다른 버킷**에 중복 저장, 검색 실패 |
| [`HashAndEqualsMain2`](../collection/set/member/HashAndEqualsMain2.java) `MemberOnlyHash` | ✅ | ❌ | 같은 버킷엔 가지만 `equals` 실패 → `['A', 'A']` 중복, 검색 실패 |
| [`HashAndEqualsMain3`](../collection/set/member/HashAndEqualsMain3.java) `Member` | ✅ | ✅ | 중복 저장 안 됨 (`add` → `false`) |

규칙: **`equals`가 `true`인 두 객체는 `hashCode`가 반드시 같아야 한다.** 반대(해시가 같으면 equals도 true)는 아니다 — `"Aa"`와 `"BB"`는 둘 다 2112로 충돌하지만 다른 값이다.

⚠️ 내 `HashAndEqualsMain3`의 "검색 성공" 부분은 `searchValue`를 `Member`가 아니라 **`MemberOnlyHash`** 로 만들어서 실제 결과는 `contains = false`다(실행해서 확인). `LinkedList.contains`는 `searchValue.equals(원소)`를 호출하는데, `MemberOnlyHash`는 `equals`가 없어 참조 비교로 떨어진다. `new Member("A")`로 바꾸면 `true`.

💡 IntelliJ `Generate → equals() and hashCode()`로 만들면 된다. 둘은 **항상 같이** 만든다.

리스트와 같은 흐름: 인터페이스로 추상화 → 구현 교체 가능, 제네릭으로 타입 안전.

## ✅ 핵심 요약

- 객체 → `hashCode()` → `Math.abs() % capacity` → 버킷 → `equals()`로 비교.
- 해시 자료 구조에 넣는 객체는 **`hashCode` + `equals`를 반드시 함께 오버라이딩**.
- `equals`가 같으면 `hashCode`도 같아야 한다. 해시가 같다고 같은 객체는 아니다(충돌).
