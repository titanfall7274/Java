# 00. 전체 리뷰 — 제네릭과 컬렉션 한 장 정리

> 김영한 자바 중급편 2 (01~10장)를 복습용으로 한 문서에 압축했다.
> 자세한 설명·내 코드 인용은 각 챕터 문서로 넘긴다. 이 문서는 **"한 번에 훑고, 셀프 체크로 확인"** 용도.

---

## 흐름 한눈에

```
제네릭 (01~02)            타입 안전 + 재사용 — 이후 모든 컬렉션의 기반
   ↓
List (03~05)              배열 → 동적 배열 → 연결 리스트 → 인터페이스 추상화 / DI
   ↓
해시 · Set (06~08)        검색 O(1) — hashCode + equals, Hash/LinkedHash/Tree
   ↓
Map · Stack · Queue (09)  키-값, LIFO, FIFO → Deque 하나로
   ↓
순회 · 정렬 · 유틸 (10)   Iterable, Comparable/Comparator, List.of
```

## 1. 제네릭 — [01장](01.%20제네릭%20-%20Generic1.md) · [02장](02.%20제네릭%20-%20Generic2.md)

| 방식 | 재사용 | 타입 안전성 |
|------|:---:|:---:|
| 타입별 클래스 (`IntegerBox`) | ❌ | ✅ |
| `Object` 다형성 (`ObjectBox`) | ✅ | ❌ (캐스팅, `ClassCastException`) |
| 제네릭 (`Box<T>`) | ✅ | ✅ |

| 문법 | 의미 |
|------|------|
| `class Box<T>` | 제네릭 타입 — **생성 시점**에 타입 결정 |
| `<T> T m(T t)` | 제네릭 메서드 — **호출 시점**에 결정, `static` 가능 |
| `<T extends Animal>` | 상한 — `Animal` 이하만 + `Animal` 기능 사용 |
| `Box<?>` / `Box<? extends A>` / `Box<? super A>` | 와일드카드 — 받아서 쓰기만 할 때 |

- 반환 타입이 인자 타입을 따라가야 하면 `<T>`, 아니면 `?`.
- 타입 인자는 참조형만 (`Integer`). 로 타입(`new Box()`) 금지.
- **타입 이레이저**: 컴파일 후 `T`는 `Object`(상한이 있으면 상한)로 지워진다 → `new T()`, `instanceof T`, `new E[]` 불가.

## 2. List — [03장](03.%20컬렉션%20프레임워크%20-%20ArrayList.md) · [04장](04.%20컬렉션%20프레임워크%20-%20LinkedList.md) · [05장](05.%20컬렉션%20프레임워크%20-%20List.md)

| 연산 | 배열 리스트 | 연결 리스트 (자바: 이중 연결) |
|------|:---:|:---:|
| 인덱스 조회 | **O(1)** | O(n) |
| 검색 | O(n) | O(n) |
| 앞에 추가·삭제 | O(n) (밀기) | **O(1)** |
| 중간 추가·삭제 | O(n) | O(n) |
| 뒤에 추가·삭제 | O(1) | O(1) |

- 배열 리스트 = `Object[]` + `size` + 꽉 차면 `grow()`(자바는 1.5배). 제네릭이어도 내부는 `Object[]`, 꺼낼 때 `(E)`.
- 연결 리스트 = 노드(`item`, `next`)를 참조로 연결. `Node`는 `private static` 중첩 클래스.
- **인터페이스(`MyList`)에 의존, 구현체는 생성자로 주입(DI)** → 사용 코드 변경 없이 교체(OCP).
  컴파일 타임엔 인터페이스, 런타임엔 실제 구현체에 의존.
- 실측은 캐시 지역성·`arraycopy` 덕분에 **`ArrayList`가 대부분 우세** → 기본값은 `ArrayList`.

## 3. 해시 · Set — [06장](06.%20컬렉션%20프레임워크%20-%20해시(Hash).md) · [07장](07.%20컬렉션%20프레임워크%20-%20HashSet.md) · [08장](08.%20컬렉션%20프레임워크%20-%20Set.md)

```
객체 ─hashCode()─▶ 해시 코드 ─Math.abs() % capacity─▶ 해시 인덱스 ─▶ 버킷 ─equals()─▶ 같은 값?
```

- Set은 추가 때마다 중복 검사 → **검색 성능 = 추가 성능**. 해시로 평균 O(1).
- 충돌(다른 값, 같은 인덱스)은 버킷(리스트)에 함께 저장. 자바는 75% 차면 2배로 늘린다.
- **`hashCode` + `equals`는 항상 같이 오버라이딩.** `equals`가 같으면 `hashCode`도 같아야 한다.

| hashCode | equals | 해시 자료 구조 결과 |
|:---:|:---:|------|
| ❌ | ❌ | 다른 버킷 → 중복 저장, 검색 실패 |
| ✅ | ❌ | 같은 버킷, 비교 실패 → 중복 저장, 검색 실패 |
| ✅ | ✅ | 정상 |

| Set | 순서 | 복잡도 | 필요 조건 |
|-----|------|:---:|----------|
| `HashSet` | 없음 | O(1) | `equals`/`hashCode` |
| `LinkedHashSet` | 입력 순 | O(1) | `equals`/`hashCode` |
| `TreeSet` | 정렬 순 (레드-블랙 트리) | O(log n) | `Comparable` 또는 `Comparator` |

- 집합 연산: 합 `addAll`, 교 `retainAll`, 차 `removeAll`.

## 4. Map · Stack · Queue — [09장](09.%20컬렉션%20프레임워크%20-%20Map,%20Stack,%20Queue.md)

- Map: 키 중복 불가, 같은 키 `put` → **덮어쓰기**. `get`은 없으면 `null`.
- 자주 쓰는 것: `getOrDefault`, `putIfAbsent`, `containsKey`, 순회는 `entrySet()`.
- `HashMap` / `LinkedHashMap` / `TreeMap` ↔ `HashSet` / `LinkedHashSet` / `TreeSet` (Set은 Map의 키만 쓰는 것).
- 스택 LIFO(`push`/`pop`/`peek`), 큐 FIFO(`offer`/`poll`/`peek`) — **둘 다 `ArrayDeque`**. `Stack` 클래스는 쓰지 않는다(`Vector` 기반, 느림).
- 큐는 `Queue` 타입으로 선언해 기능을 제한할 수 있지만, 스택은 전용 인터페이스가 없어 `Deque`로 선언한다.

## 5. 순회 · 정렬 · 유틸 — [10장](10.%20컬렉션%20프레임워크%20-%20순회,%20정렬,%20전체%20정리.md)

- `Iterable.iterator()` → `Iterator.hasNext()/next()`. `Iterable`이면 for-each 가능(컴파일러가 while문으로 변환). 모든 `Collection`은 `Iterable`, `Map`은 아니다.
- `Comparable.compareTo` = 클래스 안 기본 정렬 1개, `Comparator.compare` = 밖에서 여러 기준. 음수/0/양수. 역순 `reversed()`.
- `Arrays.sort(arr[, cmp])`, `list.sort(cmp 또는 null)`, `new TreeSet<>(cmp)`.
- `List.of` 불변·원본 복사 / `Arrays.asList` 크기 고정·원본 배열 공유 / 가변이 필요하면 `new ArrayList<>(...)`.
- `Collections.max/min/shuffle/sort/reverse`, `unmodifiableXxx`, `synchronizedList`.

## 전체 구조와 기본 선택

```
Iterable
 └ Collection
    ├ List  ── ArrayList ★, LinkedList
    ├ Set   ── HashSet ★ ─ LinkedHashSet,  TreeSet
    └ Queue ── Deque ─ ArrayDeque ★, LinkedList
Map ── HashMap ★ ─ LinkedHashMap,  TreeMap
                                        ★ = 특별한 이유 없으면 이것
```

## ⚠️ 내 실습 코드에서 발견한 버그 (복습 포인트)

실습 코드를 정리하며 실행해 확인한 것들이다. 코드는 그대로 두고 기록만 한다.

| 위치 | 문제 | 올바른 코드 |
|------|------|------------|
| `collection.list.MyLinkedList.add(0, e)` | `newNode.next = first` 누락 → 기존 노드 전부 유실, 5장 성능 수치가 왜곡됨 | `newNode.next = first; first = newNode;` |
| `collection.set.HashStart5.contains` | 버킷에서 `hashIndex`를 찾음 | `bucket.contains(searchValue)` |
| `collection.set.MyHashSetV1.remove` | 삭제 실패해도 `size--` | 성공 시에만 감소 (V2 방식) |
| `collection.set.member.HashAndEqualsMain3` | 검색값을 `MemberOnlyHash`로 생성 → `false` | `new Member("A")` |
| `collection.compare.SortMain2.DescComparator` | `* -1`이 일부에만 적용 → 비교 규칙 위반 | `Integer.compare(o2, o1)` |
| `collection.list.JavaListPerformanceTest` | ArrayList 블록에서 `addMid(new LinkedList<>())` | `new ArrayList<>()` |

## 셀프 체크

<details>
<summary>1. <code>Object</code>로 만든 박스 대신 제네릭을 쓰는 이유 두 가지는?</summary>

꺼낼 때 캐스팅이 필요 없고, 잘못된 타입을 넣으면 **컴파일 시점**에 막힌다. 동시에 클래스 하나로 여러 타입을 재사용한다.
</details>

<details>
<summary>2. <code>AnimalHospital&lt;T&gt;</code>에서 <code>animal.getName()</code>이 컴파일 안 되는 이유와 해결은?</summary>

`T`에 무엇이 올지 모르니 `Object`로 간주해 `Object` 메서드만 쓸 수 있다. `<T extends Animal>`로 상한을 건다.
</details>

<details>
<summary>3. <code>static</code> 메서드에서 클래스의 <code>T</code>를 못 쓰는데 제네릭 메서드는 되는 이유는?</summary>

클래스의 `T`는 객체 생성 시 정해지는데 `static`은 객체 없이 호출된다. 제네릭 메서드의 `<T>`는 호출할 때 정해진다.
</details>

<details>
<summary>4. <code>maxHp(T a, T b)</code>를 와일드카드로 만들면 안 되는 이유는?</summary>

와일드카드는 반환 타입을 인자에 맞춰 바꿀 수 없어 상한 타입(`BioUnit`)만 반환된다. `Zealot`을 넣고 `Zealot`을 돌려받으려면 `<T extends BioUnit>`.
</details>

<details>
<summary>5. <code>new T()</code>, <code>new E[10]</code>이 안 되는 이유는?</summary>

타입 이레이저 — 런타임에는 `T`가 지워져 무엇을 만들어야 할지 모른다. 그래서 배열 리스트도 내부는 `Object[]`.
</details>

<details>
<summary>6. 앞에 5만 번 추가할 때 ArrayList와 LinkedList 중 빠른 쪽은? 인덱스 조회는?</summary>

앞 추가는 LinkedList(O(1) vs 밀기 O(n)). 인덱스 조회는 ArrayList(O(1) vs O(n)).
</details>

<details>
<summary>7. <code>BatchProcessor</code>가 <code>MyList</code>를 생성자로 받는 이유는?</summary>

구현체를 바꿀 때 `BatchProcessor` 코드를 고치지 않기 위해 (DI, OCP). 컴파일 타임엔 인터페이스에만 의존하고 런타임에 실제 구현이 정해진다.
</details>

<details>
<summary>8. 해시 인덱스를 구할 때 <code>Math.abs()</code>가 필요한 이유는?</summary>

`hashCode()`가 음수일 수 있고, 음수 `%` 결과도 음수라 배열 인덱스로 못 쓴다.
</details>

<details>
<summary>9. <code>hashCode</code>만 오버라이딩하고 <code>equals</code>는 안 하면 HashSet에서 어떻게 되나?</summary>

같은 버킷까지는 가지만 `equals`가 참조 비교라 같은 내용을 다른 값으로 본다 → 중복 저장, 검색 실패.
</details>

<details>
<summary>10. 중복 제거 + 입력 순서 유지 / 중복 제거 + 정렬 은 각각 무엇을 쓰나?</summary>

`LinkedHashSet` / `TreeSet`.
</details>

<details>
<summary>11. 단어 빈도를 세는 Map 코드를 한 줄로?</summary>

`map.put(word, map.getOrDefault(word, 0) + 1);`
</details>

<details>
<summary>12. 스택이 필요할 때 <code>Stack</code> 대신 무엇을 쓰고 왜?</summary>

`Deque<Integer> stack = new ArrayDeque<>();` — `Stack`은 `Vector` 기반이라 오래되고 느리다.
</details>

<details>
<summary>13. 직접 만든 클래스를 for-each로 돌리려면?</summary>

`Iterable<T>`를 구현해 `iterator()`에서 `Iterator<T>`(`hasNext`, `next`)를 돌려준다.
</details>

<details>
<summary>14. <code>Comparable</code>과 <code>Comparator</code>는 언제 각각 쓰나?</summary>

객체의 기본 정렬 기준 하나는 클래스 안 `Comparable`, 다른 기준이 필요하면 밖에서 `Comparator`를 만들어 넘긴다.
</details>

<details>
<summary>15. <code>Arrays.asList(arr)</code> 후 <code>arr[0]</code>을 바꾸면? <code>List.of(arr)</code>는?</summary>

`asList`는 원본 배열을 공유하므로 리스트도 바뀐다. `List.of`는 복사본이라 그대로다. 둘 다 크기 변경은 불가, `List.of`는 원소 변경도 불가.
</details>
