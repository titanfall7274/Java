## 1. Map 소개

**키-값 쌍** 저장. 키는 중복 불가, 값은 중복 가능. 순서 보장 안 함.

| 메서드 | 동작 |
|--------|------|
| `put(k, v)` | 저장. **같은 키면 값 덮어쓰기** ([`MapMain2`](../collection/map/MapMain2.java)) |
| `get(k)` | 조회, 없으면 `null` |
| `getOrDefault(k, d)` | 없으면 `d` |
| `putIfAbsent(k, v)` | 키가 **없을 때만** 저장 ([`MapMain3`](../collection/map/MapMain3.java)) |
| `containsKey(k)` / `remove(k)` | 존재 확인 / 삭제 |
| `keySet()` / `values()` / `entrySet()` | 키 `Set` / 값 `Collection` / 키-값 `Set<Map.Entry>` |

```java
// MapMain1 — 전체 순회는 entrySet이 가장 깔끔하다
for (Map.Entry<String, Integer> entry : studentMap.entrySet()) {
    String key = entry.getKey();
    Integer value = entry.getValue();
}
```

- `keySet()`이 `Set`인 이유: 키는 중복이 없고 순서도 없으니까. `values()`는 중복 가능이라 `Collection`.

## 2. Map 구현체

Map의 키는 Set과 같은 방식으로 관리된다 — **`HashSet`은 내부적으로 `HashMap`을 쓰고 값 자리만 비워 둔 것**이다.

| 구현체 | 키 순서 | 복잡도 | 대응 Set |
|--------|---------|:---:|----------|
| `HashMap` | 없음 | O(1) | `HashSet` |
| `LinkedHashMap` | 입력 순 | O(1) | `LinkedHashSet` |
| `TreeMap` | 키 정렬 순 | O(log n) | `TreeSet` |

⚠️ `HashMap`의 **키**로 쓰는 객체는 `equals`/`hashCode`를 오버라이딩해야 한다 — [`Cart`](../collection/map/test/cart/Cart.java)의 `Map<Product, Integer>`에서 `Product`가 그렇게 되어 있기 때문에 같은 사과를 다시 담으면 수량이 합쳐진다.

## 3. 스택 자료 구조

**후입 선출(LIFO)** — 마지막에 넣은 것이 먼저 나온다. `push` / `pop` / `peek`(꺼내지 않고 보기).

⚠️ 자바 `Stack` 클래스는 **쓰지 않는다** — 내부가 `Vector`라 오래된 구조이고 동기화 때문에 느리다. **`Deque`를 대신 쓴다.**

## 4. 큐 자료 구조

**선입 선출(FIFO)** — 먼저 넣은 것이 먼저 나온다. `offer`(넣기) / `poll`(꺼내기) / `peek`.

```java
Queue<Integer> queue = new ArrayDeque<>(); // 훨씬 빠름
```

```
Collection ─ Queue ─ Deque ─┬─ ArrayDeque
                            └─ LinkedList   (List도 구현)
```

## 5. Deque 자료 구조

**양쪽 끝**에서 넣고 뺄 수 있는 큐 (Double Ended Queue).

```java
// DequeMain
deque.offer(1);       // offerLast 호출
deque.offerFirst(2);
deque.offerLast(3);   // [2, 1, 3]
deque.poll();         // pollFirst() 호출
deque.pollLast();
```

- `ArrayDeque` : 원형 큐 형태의 배열. 양 끝 O(1)이고 **실측상 `LinkedList`보다 빠르다** → 기본 선택.

## 6. Deque와 Stack, Queue

`Deque` 하나로 스택과 큐를 모두 쓴다.

| 용도 | 선언 | 쓰는 메서드 |
|------|------|------------|
| 스택 | `Deque<Integer> stack = new ArrayDeque<>();` | `push`, `pop`, `peek` |
| 큐 | `Queue<Integer> queue = new ArrayDeque<>();` | `offer`, `poll`, `peek` |

> 내 주석(`DequeQueueMain`): *"Queue는 Queue인터페이스가 있어 제한이 가능하다."*
> 내 주석(`DequeStackMain`): *"Stack은 따로 interface가 없어 제한이 불가능하다. 사용할때 주의가 필요하다."*

→ 큐는 `Queue` 타입으로 선언하면 큐 메서드만 보이지만, 스택은 `Deque`로 선언할 수밖에 없어 `offerLast` 같은 다른 메서드도 열려 있다.

## ✅ 핵심 요약

- Map: 키 중복 불가, 같은 키 `put`은 덮어쓰기. 순회는 `entrySet()`.
- Map 구현체 선택은 Set과 동일: `HashMap`(기본) / `LinkedHashMap`(입력 순) / `TreeMap`(정렬).
- 스택(LIFO)·큐(FIFO) 모두 **`ArrayDeque`** 로. `Stack` 클래스는 쓰지 않는다.
