## 1. 타입 매개변수 제한

동물 병원 예제를 4단계로 바꿔 가며 문제를 푼다.

| 단계 | 코드 | 재사용 | 타입 안전성 | 문제 |
|------|------|:---:|:---:|------|
| V0 | `DogHospital`, `CatHospital` | ❌ | ✅ | 클래스 중복 |
| V1 | `AnimalHostpitalV1` (`Animal` 다형성) | ✅ | ❌ | 개 병원에 고양이가 들어가도 컴파일 OK, 반환 시 `(Dog)` 캐스팅 |
| V2 | `AnimalHostpitalV2<T>` | ✅ | ❌ | `T`에 `Integer`도 들어가고, `T`는 `Object` 기능만 씀 → `getName()` 호출 불가 |
| V3 | `AnimalHostpitalV3<T extends Animal>` | ✅ | ✅ | 해결 |

```java
// 타입 매개변수 상한을 사용하여 타입을 제한하여 타입 안정성을 만족할 수 있습니다.
public class AnimalHostpitalV3<T extends Animal> {
    private T animal;
    public void checkUp() {
        System.out.println("동물 이름: " + animal.getName()); // Animal 기능 사용 가능
        animal.sound();
    }
    public T bigger(T target) { ... } // Dog 병원이면 Dog 반환, 캐스팅 불필요
}
```

`<T extends Animal>` 하나로 두 가지를 얻는다.
1. `T`에 `Animal`과 그 자식만 들어온다 → `AnimalHostpitalV3<Integer>`는 컴파일 에러.
2. `T`를 `Animal`로 간주하므로 `Animal`의 메서드를 쓸 수 있다.

## 2. 제네릭 메서드

클래스가 아니라 **메서드 단위**로 타입 매개변수를 둔다. 반환 타입 앞에 `<T>`.

```java
// GenericMethod
public static <T> T genericMethod(T t) { ... }
public static <T extends Number> T numberMethod(T t) { ... }  // 상한도 가능

Integer a = GenericMethod.<Integer>genericMethod(i); // 명시
Integer b = GenericMethod.genericMethod(i);          // 추론 (보통 이렇게 쓴다)
```

| | 제네릭 타입 `class X<T>` | 제네릭 메서드 `<T> T m(T t)` |
|---|---|---|
| 타입 결정 시점 | 객체 **생성** 시 | 메서드 **호출** 시 |
| `static` 메서드에서 | ❌ `T` 사용 불가 | ✅ 가능 |

⚠️ 내 주석: *"제네릭 타입은 static 메서드에 타입 매개변수를 사용하지는 못한다. 객체를 생성하는 시점에 타입이 정해지기 때문이다."* — `static`은 객체 없이 호출되기 때문.

💡 클래스의 `T`와 메서드의 `<T>` 이름이 같으면 **메서드 쪽이 우선**한다. 헷갈리니 `ComplexBox`처럼 `<Z>` 등 다른 이름을 쓰자.

## 3. 제네릭 메서드 활용

병원 클래스 없이 유틸 메서드로 같은 기능을 낸다 ([`AnimalMethod`](../generic/ex4/AnimalMethod.java)).

```java
// 반드시 타입 상한을 걸어야 Animal에 작성된 메서드들을 사용할 수 있다.
public static <T extends Animal> T bigger(T target1, T target2) {
    return target1.getSize() > target2.getSize() ? target1 : target2;
}

```

## 4. 와일드카드

`?` = **이미 만들어진 제네릭 타입을 받아서 쓰기만 할 때** 사용하는 "아무 타입". 제네릭 메서드가 아니라 일반 메서드다.

```java
static void printWildcardV1(Box<?> box)                    // 비제한: ? == Object
static void printWildcardV2(Box<? extends Animal> box)     // 상한: Animal 이하
static void writeBox(Box<? super Animal> box)              // 하한: Animal 이상 (Object, Animal)
```

제네릭 메서드와의 결정적 차이 — **반환 타입**:

```java
static <T extends Animal> T printAndReturnGeneric(Box<T> box)          // Dog 넣으면 Dog 반환
static Animal printAndReturnWildcard(Box<? extends Animal> box)       // 항상 Animal 반환
```

> 내 주석: *"제네릭 타입이나 제네릭 메서드가 꼭 필요하다면 `<T>`를 사용하고, 그렇지 않은 경우에는 와일드 카드를 사용하는 것을 권장한다."*

⚠️ 하한 와일드카드 `? super`는 **와일드카드에만 있고** 타입 매개변수(`<T super X>`)에는 없다.

## 5. 타입 이레이저

제네릭은 **컴파일 단계에서만** 존재한다. 컴파일러가 타입을 검사하고 필요한 캐스팅을 넣은 뒤, `.class`에서는 `T`를 지운다 (`T` → `Object`, `T extends Animal` → `Animal`).

그래서 **런타임에 `T`가 뭔지 모른다** → 아래 두 개가 불가능하다 ([`EraseBox`](../generic/ex5/EraseBox.java)).

```java
// return param instanceof T; // 오류 — 지워지면 instanceof Object, 항상 true
// return new T();            // 오류 — 지워지면 new Object()
```

## ✅ 핵심 요약

- `<T extends 상위>` → 들어올 타입 제한 + 상위 타입 기능 사용.
- 제네릭 메서드는 **호출 시점**에 타입이 정해지고 `static`에서도 쓸 수 있다.
- 반환 타입이 인자 타입을 따라가야 하면 `<T>`, 받아서 읽기만 하면 `?`.
- 이레이저: 런타임엔 `T`가 없다 → `instanceof T`, `new T()` 불가.
