## 1. 배열의 특징1 - 배열과 인덱스

배열은 메모리에 **연속**으로 붙어 있다. 그래서 `시작 주소 + (원소 크기 × 인덱스)` 한 번의 계산으로 위치를 찾는다.

| 연산 | 복잡도 | 이유 |
|------|:---:|------|
| 인덱스 입력·변경·조회 | O(1) | 주소 계산 한 번 |
| 값으로 검색 | O(n) | 처음부터 하나씩 비교 ([`ArrayMain1`](../collection/array/ArrayMain1.java)) |

## 2. 빅오(O) 표기법

입력 크기 n이 커질 때 **연산 횟수가 늘어나는 추세**만 본다. 상수와 낮은 차수는 버린다 (`O(2n)` → `O(n)`, `O(n² + n)` → `O(n²)`). 보통 최악의 경우를 기준으로 한다.

`O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)`

## 3. 배열의 특징2 - 데이터 추가

| 위치 | 복잡도 | 작업 ([`ArrayMain2`](../collection/array/ArrayMain2.java)) |
|------|:---:|------|
| 마지막 | O(1) | 그냥 넣는다 |
| 처음 / 중간 | O(n) | 넣을 자리부터 **뒤로 한 칸씩 밀고** 넣는다 |

```java
private static void addAtIndex(int[] arr, int index, int value) {
    for (int i = arr.length - 1; i > index; i--) {
        arr[i] = arr[i - 1];   // 뒤에서부터 한 칸씩 민다
    }
    arr[index] = value;
}
```

⚠️ 배열의 가장 큰 한계: **크기를 생성 시점에 정해야 하고 바꿀 수 없다.**

## 4. 직접 구현하는 배열 리스트 — 시작 → 동적 배열 → 기능 추가

| 버전 | 추가된 것 |
|------|-----------|
| V1 | `Object[] elementData` + `size`. 용량 초과 시 `ArrayIndexOutOfBoundsException` |
| V2 | `grow()` — 꽉 차면 **2배 크기 새 배열에 복사**하고 참조 교체 |
| V3 | `add(index, e)` (오른쪽으로 밀기), `remove(index)` (왼쪽으로 당기기) |

```java
// MyArrayListV2
public void add(Object e) {
    if (size == elementData.length) {
        grow(); // 크기를 2배로 증가 및 레퍼런스 변경
    }
    elementData[size] = e;
    size++;
}
private void grow() {
    elementData = Arrays.copyOf(elementData, elementData.length * 2);
}
```

- `size`(실제 개수)와 `capacity`(`elementData.length`, 배열 크기)는 다르다. `toString()`도 `Arrays.copyOf(elementData, size)`로 **size까지만** 보여 준다.
- `remove` 후 마지막 칸을 `null`로 비워야 참조가 남지 않는다 (GC 대상이 되도록).
- 💡 자바 `ArrayList`는 2배가 아니라 **약 1.5배**씩 늘린다. 기본 용량은 10.

## 5. 직접 구현하는 배열 리스트 — 제네릭

V3는 `Object`라서 아무거나 들어가고 꺼낼 때 터진다 ([`MyArrayListV3BadMain`](../collection/array/MyArrayListV3BadMain.java)).

```java
numberList.add("문자3");
Integer number = (Integer) numberList.get(2); // ClassCastException 발생, (Integer) String
```

V4에서 `MyArrayListV4<E>`로 바꾼다. 그런데 **내부 배열은 여전히 `Object[]`** 다.

```java
private Object[] elementData;           // new E[] 는 불가능 (타입 이레이저)

@SuppressWarnings("unchecked")
public E get(int index) {
    return (E) elementData[index];      // add(E e)로만 넣으므로 안전한 캐스팅
}
```

- `new E[5]`는 컴파일 에러 — 런타임에 `E`가 지워져 무엇을 만들지 모른다 ([02장 5절](02.%20제네릭%20-%20Generic2.md#5-타입-이레이저)).
- 넣는 입구(`add(E)`)가 `E`만 받으므로 꺼낼 때 `(E)` 캐스팅은 항상 안전하다.

## ✅ 핵심 요약

- 배열: 인덱스 접근 O(1), 검색 O(n), 앞·중간 삽입/삭제 O(n)(밀기), 끝 추가 O(1).
- 배열 리스트 = 배열 + `size` + 꽉 차면 **더 큰 배열로 복사**(`grow`).
- 제네릭 배열 리스트도 내부는 `Object[]`, 꺼낼 때 `(E)` 캐스팅.
