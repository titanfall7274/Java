## 1. 리스트 추상화1 - 인터페이스 도입

배열 리스트와 연결 리스트는 **내부 구현만 다르고 제공하는 기능은 같다.** 공통 기능을 인터페이스로 뽑는다.

```java
public interface MyList<E> {
    int size();
    void add(E e);
    void add(int index, E e);
    E get(int index);
    E set(int index, E element);
    E remove(int index);
    int indexOf(E o);
}
public class MyArrayList<E> implements MyList<E> { ... }
public class MyLinkedList<E> implements MyList<E> { ... }
```

## 2. 리스트 추상화2 - 의존관계 주입

`BatchProcessor`가 구체 클래스를 직접 `new` 하면, 구현을 바꿀 때마다 `BatchProcessor` 코드를 고쳐야 한다. **인터페이스에 의존하고 구현체는 밖에서 넣어 준다.**

```java
public class BatchProcessor {
    private final MyList<Integer> list;
    // 밖에서 나중에 의존관계를 결정하여 주입
    public BatchProcessor(MyList<Integer> list) {
        this.list = list;
    }
}

// BatchProcessorMain — 이 한 줄만 바꾸면 된다
MyList<Integer> integerList = new MyLinkedList<>();
new BatchProcessor(integerList).logic(50_000);
```

이게 **의존관계 주입(DI)** 이고, "확장에는 열려 있고 변경에는 닫혀 있다" — **OCP** 원칙이다.

## 3. 리스트 추상화3 - 컴파일 타임, 런타임 의존관계

| 구분 | 무엇에 의존하나 | 어디서 보이나 |
|------|----------------|--------------|
| 컴파일 타임 | `MyList` (인터페이스) | `BatchProcessor` 소스 코드 |
| 런타임 | `MyArrayList` 또는 `MyLinkedList` 인스턴스 | 실행 중 생성자로 들어온 객체 |

`BatchProcessor`는 컴파일 타임엔 `MyList`만 안다. 무엇을 쓸지는 **런타임에 클라이언트가 결정**한다 — 이 구조가 Spring의 핵심이기도 하다.

## 4. 직접 구현한 리스트의 성능 비교

[`MyListPerformanceTest`](../collection/list/MyListPerformanceTest.java) (5만 건, 내 PC 기록)

| 연산 | MyArrayList | MyLinkedList |
|------|:---:|:---:|
| 앞에 추가 | 2807ms · O(n) | 6ms · O(1) |
| 중간에 추가 | 1651ms · O(n) | 898ms · O(n) |
| 뒤에 추가 | O(1) | O(n) |
| 인덱스 조회 | O(1) | O(n) |
| 검색 | O(n) | O(n) |

⚠️ **내 `MyLinkedList.add(0, e)`에 버그가 있다** — `index == 0`일 때 `newNode.next = first;`가 빠져서 **기존 노드를 전부 잃어버린다.** 앞에만 5번 넣으면 `size`는 5인데 노드는 1개라 `get(1)`에서 `NullPointerException`이 난다(실행해서 확인). 그래서 위 표와 `BatchProcessorMain`의 "LinkedList: 5ms"는 **노드 1개짜리 리스트를 잰 값**이다. 연결 리스트 앞 추가가 O(1)이라는 결론 자체는 맞지만, 수치는 버그를 고친 뒤 다시 재야 한다. 올바른 코드는 [04장 3절](04.%20컬렉션%20프레임워크%20-%20LinkedList.md#3-직접-구현하는-연결-리스트--추가와-삭제)의 `MyLinkedListV2`.

## 5. 자바 리스트 (ArrayList, LinkedList)

```
Collection ─ List ─┬─ ArrayList
                   └─ LinkedList
```

| | `ArrayList` | `LinkedList` |
|---|---|---|
| 구조 | 동적 배열 (기본 용량 10, **50%씩** 증가) | **이중** 연결 리스트 (`first`, `last`) |
| 앞 추가·삭제 | O(n) | O(1) |
| 뒤 추가·삭제 | O(1) | O(1) |
| 인덱스 조회 | O(1) | O(n) |

💡 자바 `ArrayList`는 밀기를 `System.arraycopy`로 **메모리 블록 단위 고속 복사**를 해서, 이론상 O(n)이라도 직접 만든 것보다 훨씬 빠르다.

## 6. 자바 리스트의 성능 비교

[`JavaListPerformanceTest`](../collection/list/JavaListPerformanceTest.java)로 같은 실험을 자바 구현체에 돌린다.

- 이론상 중간 삽입은 둘 다 O(n)이지만 **실측에선 `ArrayList`가 더 빠르다** — 연속 메모리라 CPU 캐시 효율이 좋고, `arraycopy` 덕분.
- 결론: **대부분 `ArrayList`를 기본으로 쓴다.** 앞쪽 추가·삭제가 매우 잦을 때만 `LinkedList`를 고려.

⚠️ 내 코드에서 `== ArrayList 추가==` 블록의 두 번째 줄이 `addMid(new LinkedList<>(), size)`로 되어 있다 — 라벨과 달리 `LinkedList`를 재고 있으니 `ArrayList`로 바꿔야 비교가 맞다.

## ✅ 핵심 요약

- 구현이 달라도 기능이 같으면 **인터페이스로 추상화** → 사용하는 쪽은 인터페이스에만 의존.
- **DI**: 구현체를 생성자로 받아 런타임에 결정 → 사용 코드 변경 없이 교체(OCP).
- 실무 기본값은 **`ArrayList`**. 앞쪽 삽입·삭제가 압도적으로 많을 때만 `LinkedList`.
